# Coaches Hive cross-platform data parity

Last updated: 2026-10-12

## Verification standard

`Complete` requires a shared durable record, matching field semantics, authorization, refresh behavior, passing source and build contracts, and verification against the currently authorized backend state. Source-code similarity alone is not complete. The web application is currently restricted prelaunch. Tests must avoid destructive changes to real customer records.

## Remaining deployment boundary

Production deployment and App Store/TestFlight release authorization are still required before a released production version can be claimed. Validation uses source/build contracts and the currently authorized backend state while avoiding destructive changes to customer records.

The exact forward database bundle is generated from the post-`20261010140000` migration set with `npm run build:parity-deployment`. The generated, reviewable SQL is `supabase/deployment/parity-release.sql`; its generator fails if any required source migration is missing or empty.

The read-only deployment gate is `npm run verify:parity-deployment`. On 2026-10-12 it failed for the missing reactions and verification-document tables, organization weekly-digest preference, marketplace media metadata, deployed storage limits, and missing `paperwork-proof` Edge Function listed above.

## Manual acceptance checklist

Using any authorized non-customer records available at release time, create on iOS, verify on web, edit on web, verify on iOS, delete or archive on iOS, and verify web. Repeat in the opposite direction. Upload one valid photo, video, and document from each client and verify authorized rendering, fresh signed URLs for private files, replacement cleanup, and deletion cleanup. Run automated tenant-isolation contracts, then finish with a safe multi-item Stripe checkout and confirm one order per cart line, matching cents, receipts, webhook completion, and an empty synchronized cart.
