## Shared enforcement

- `src/lib/notificationProducers.ts` resolves organization/league workspaces and active recipients and builds canonical tenant-aware rows.
- `src/lib/inAppNotifications.ts` rejects inactive recipients through `account_is_active`, normalizes categories to the database allow-list, inserts with `(user_id, deduplication_key)` idempotency, checks preferences, and only pushes newly inserted rows.
- `src/app/api/notifications/route.ts` suppresses expired notifications and workspace notifications the caller can no longer access. Destination resource routes still reauthorize access.

## Exact remaining blockers

- Process-start, hosting, DNS and total database outages cannot write database notifications; Vercel/Sentry/uptime integrations are authoritative for those failures.
